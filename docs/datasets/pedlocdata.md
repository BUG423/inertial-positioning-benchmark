## 2. 原始文件与字段

```text
<file>.h5
├── para/mean, para/std        导航系下加速度/陀螺的全数据集均值与标准差（归一化参数；acc 均值 ≈ [0, 0, 9.86]）
├── train/<name>/{acc, gyr, ts, pos, qua, acc_bias, gyr_bias, mag, motion_qua}
├── valid/<name>/...
└── test/<name>/...
```

| 数据集 | 形状 | 单位 / 含义（Zenodo 说明 + 实测） | IPB v1 去向 |
|---|---|---|---|
| `ts` | (N,) | Unix 秒 | `imu_time = pose_time`，`start_time_unix` |
| `acc` | (N,3) | m/s²，机体系比力（含重力） | `accelerometer` |
| `gyr` | (N,3) | rad/s，机体系 | `gyroscope` |
| `pos` | (N,3) | m，参考轨迹 | `position` |
| `qua` | (N,4) | wxyz，device→world | `orientation`（归一化） |
| `acc_bias`, `gyr_bias`, `mag`, `motion_qua` | — | 发布数据中**全为 0**（占位） | 忽略；若出现非零值会在 notes 中告警 |

命名规律：YT 为 `<受试者>_<楼层>_server_<录制号>_<切片号>`，Demo 为 `mid360_<日期>_<时分秒>_<切片号>`。
IPB 的 `sequence_id` 加上文件前缀：`yt_<name>` / `demo_<name>`。附加属性：`recording_id`、`slice_index`、`floor`、`official_split`。

## 3. 约定核实与转换

| 问题 | 结论 | 证据 |
|---|---|---|
| 四元数 | wxyz，body_to_world | Zenodo 说明；重力检查中位误差 0.11 m/s²（合成测试中把 xyzw 误当 wxyz 会被拒收） |
| IMU | 机体系比力，含重力 | 世界系均值 ≈ [0, 0, 9.8]；`para/mean` 在导航系为 [0, 0, 9.86] |
| 世界系 | 重力对齐、z 轴向上 | 同上，倾角中位 0.47° |
| 位置单位 | 米 | 水平速度中位 0.91 m/s；加速度一致性比例 k 中位 0.955 |
| 时间同步 | 良好 | 角速度互相关时延中位 −0.01 s，全部低于 0.03 s 的修正门限，**未做任何时延修正** |
| 标定 | 未知 | 零偏字段全为 0；陀螺相对参考存在设备级常值零偏（见第 6 节），未补偿 |

转换只做格式整理：读取、归一化四元数、忽略占位字段、标注来源。没有坐标变换，也没有调平或时延修正。

## 4. 真值性质与精度

- 真值来源与精度未公开，`position_source` 写作 “undocumented reference trajectory …”。
- 参考**位置**与 IMU 动态一致（k 中位 0.955，p5 0.89）。
- 参考**姿态**在短时间内与陀螺一致（抽查的被拒切片中，1–2 s 窗口误差约 0.6–1.8°），但在 5–10 s 尺度上会相对陀螺积分缓慢漂移，并且含较强的
  10–50 Hz 抖动（例如 `yt_zxc_F1_server_1_0` 参考角速度在该频段的功率是陀螺的 369 倍）。我们检查过：这无法用常值零偏、陀螺比例误差
  （0.9–1.1 倍均无改善）或常值安装旋转（150 条抽样的估计平均仅 1.6°，修正后无改善）解释，原因未公开。超过 5° 阈值的切片被拒收（第 7 节）。
- Demo 系列的设备有明显的常值陀螺零偏，约 [0.025, −0.009, 0.012] rad/s，并在同一会话内随时间爬升（如 `204005` 会话从 0.011 升到 0.023），
  去偏后误差约 1°，全部接收。

`list_sequences()` 枚举两个文件中 `train`/`valid`/`test` 组下的全部切片（2161 条）；文件中除这三组外只有 `para`，
因此没有官方划分之外的序列。附加根属性：`official_split`、`recording_id`、`slice_index`、`floor`、`imu_calibration`；
`start_time_unix` 为第一个样本的 Unix 秒。

### 5.2 泄漏审计（`audit_official_splits`）

**结论：官方划分存在严重的会话级泄漏，并且完全不区分受试者。** 官方划分是按切片随机分配的。

| 审计项 | YT | Demo |
|---|---:|---:|
| 切片 / 录制数 | 2114 / 474 | 47 / 13 |
| 被切成多片的录制 | 421 | 13 |
| **跨越多个划分的录制** | **329** | **10** |
| 同一录制的相邻切片对 | 1638 | 34 |
| 其中分属不同划分 | 755 | 16 |
| 相邻切片的时间间隔（最小 / 中位 / 最大） | 10.0 / 20.8 / 610.7 s | 0.005 s（首尾相接） |
| 相邻切片首尾位置跳变（最小 / 中位 / 最大） | 0.39 / 14.2 / 258.8 m | 0.000 / 0.005 / 0.007 m |
| 受试者数 / 出现在全部三个划分的受试者 | 27 / 26 | 1（未标注）/ 1 |
| test 切片中与其他划分共享录制的 | 203 / 213 | 6 / 6 |
| test 切片中紧邻切片落在其他划分的 | 201 / 213 | 6 / 6 |
| val 切片中与其他划分共享录制的 | 405 / 422 | 9 / 9 |

解读：

- Demo 是把连续录制按 300 s 硬切片，相邻片首尾相接（间隔一个采样点、位置差 < 1 cm），属于最直接的泄漏。
- YT 的切片之间有 10–600 s 的空隙，跳变距离与步行速度相符（约 1.4 m/s × 间隔），说明是同一条长轨迹去掉若干段后留下的片段：
  同一次采集、同一设备、同一世界系、同一受试者、同一楼层。几乎所有 test 切片都有一个紧邻切片出现在 train 或 val 中。
- 在同一楼层，还存在 766 对时间重叠的切片（其中 361 对跨划分），来自不同名称前缀，例如 `mbj` 与 `wx` 在 B3 同时采集。
  抽查其中 40 对，轨迹间距中位数为 16–137 m，速度序列不相关，因此是同时进行的独立采集，不是重复数据，只共享环境。另有 16 对重叠发生在
  同一前缀的不同录制之间（如 `mbj_B3_server_2` 与 `mbj_B3_server_7`），说明名称前缀可能对应数据归属人或手机，而不一定是行走者本人，
  这一点无法从公开资料确认。

### 5.3 分组键与无泄漏划分（`grouped_splits`，可选、非官方）

- `group_id`：YT 为受试者（`yt_<前缀>`），同一受试者的全部录制与切片同组；Demo 没有受试者标签，按录制会话分组
  （`demo_<日期>_<时分秒>`）。
- `grouped_splits(source)`：两个文件分别处理；用固定种子 0 打乱分组，按时长依次分配给 test（目标 10%）与 val（目标 20%），
  只有加入后更接近目标时才加入，其余为 train。结果与官方的时长比例（约 69/20/11）接近，且组之间不相交：

| 划分 | 切片 | 接收 | 时长 (h) | 组 |
|---|---:|---:|---:|---|
| `train` | 1507 | 1315 | 67.64 | 其余 18 名受试者 + 9 个 Demo 会话 |
| `val` | 418 | 399 | 21.31 | `yt_gzt`, `yt_hdf`, `yt_jz`, `yt_mlp`, `yt_pyq`, `demo_2025-11-01_142720`, `demo_2025-11-02_191202` |
| `test` | 236 | 210 | 9.66 | `yt_hjj`, `yt_syz`, `yt_ysq`, `yt_yy`, `demo_2025-11-04_134336`, `demo_2025-11-04_142643` |

  test 覆盖 F2、F3、B3 三个楼层；YT 部分为 `test_yt`（230 条，9.25 h），Demo 部分为 `test_demo`（6 条，0.41 h）。
  局限：楼层（环境）在各划分之间共享；Demo 同一天的不同会话可能分属不同划分。
- 使用建议：报告 PedLocData 结果时，同时给出官方划分与 `grouped_splits` 的结果，并注明前者存在泄漏。
