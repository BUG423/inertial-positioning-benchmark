# Idea 规范约定 (ideation → experiment 交接契约)

## 存储位置

实验阶段从以下固定位置读取 idea:

```text
paperflow/
├── idea-spec-I<n>.md  # 选定 idea 详细说明书, 每个选定 idea 一份 (主推最详细, 详见模板)
├── references.md      # 结构化相关文献 (详见模板)
└── ideation.md        # 完整 10 候选清单 + 选定记录 (归档用)
```

**必须存在的最小集合**: 至少一份 `idea-spec-I<n>.md` (主推那份) + `references.md`。两者缺任一 → 实验阶段拒绝启动，提示"先跑完 ideation 落盘"。选了多个 idea 时会有 `idea-spec-I1.md` / `idea-spec-I2.md` 多份，逐份读，主推那份优先。

## idea-spec-I<n>.md 必须包含的字段

> 节标题形如 `## N. 标题` (带序号)，校验匹配标题主体即可，别死扣序号。
> ⚠️ **本文件不含任何实验设计**: idea 阶段只交代"解决什么问题 / 思路 / 创新点"，
> 主实验、消融、H1 怎么验证全部由本 (experiment) skill 设计，所以这里**不校验实验字段**。
> 字段表严格对齐 ideation 的 `templates/idea-spec.md` (9 节)。

### 必须字段

| 字段 (节标题) | 说明 | 示例 |
|------|------|------|
| `## 1. 一句话总结` | ≤30 字 | "频域设备指纹解耦 + 测试时谱对齐, 实现跨设备 IO" |
| `## 3. 设计思路（核心洞察）` ★灵魂 | 核心洞察 + 思路展开 + 为什么能解决第 2 节问题 | "设备差异活在频域而非时域语义" |
| `## 4. 核心创新点（Key Novelty）` ★灵魂 | 1-3 条, 每条配 closest work + delta (取代旧版"和 closest work 的本质区别") | "N1: 频域指纹显式解耦; closest=DWSFormer; delta=…" |
| `## 5. 技术路线` | 整体框架 + 核心模块 + 关键设计选择 (方法构想, 非实验) | 输入→backbone→关键模块→输出 |
| `## 6. 核心 Claims` | C1 (必填), C2/C3 (可选) | "跨设备设定下相比时域 baseline 显著降 ATE" |
| `## 7. 关键前提假设` | H1 (必填), H2 (可选) | "设备指纹在频域稳定且与运动可分" |
| `## 8. 关键风险 & 退路` | 至少 H1 不成立的退路 | "H1 失败 → 切 Backup I2" |
| `## 9. 预期投稿` | 评分标准 + 建议实投 venue | "按 CCF-A 标准 / 实投 CCF-C" |

### 字段校验规则

- `1. 一句话总结`: 非空，≤30 字
- `3. 设计思路`: **灵魂节，必须非空且讲清"为什么这么设计"** (含核心洞察)；含糊一句下游跑偏一片
- `4. 核心创新点`: **灵魂节，≥1 条，每条点名 closest work 的具体名称 + delta**
- `5. 技术路线`: 含"整体框架" + 至少 1 个"核心模块"
- `6. 核心 Claims.C1`: 非空，含"在 XX 设定下, 通过 XX 方法, 能做到 XX 结果"结构
- `7. 关键前提假设.H1`: 非空；最好含可验证的量化判据 (e.g. "ATE 损失<1%")，无量化判据 → 警告但放行
- `8. 关键风险 & 退路`: H1 失败退路非空
- (不校验实验设计: idea 阶段不写实验，实验由本 skill 设计)

## references.md 必须包含的字段

| 字段 | 说明 |
|------|------|
| `## 第一层: 直接竞争者` | ≤3 篇, 每篇含: 做了什么 / 差异 delta / 局限 |
| `## 第二层: 同一子方向` | 5-8 篇, 每篇含: 做了什么 / 关系 |
| `## 第三层: 方法来源` | 3-5 篇, 每篇含: 提出了什么 / 本工作怎么用 |
| `## 第四层: IO 领域基础` | 3-5 篇, 至少含 RoNIN + IONet + TLIO |
| `## 检索元信息` | query / 日期 / N 篇 / M 篇用作参考 / 源状态 |

## ideation.md 必须包含的字段 (归档用)

| 字段 | 说明 |
|------|------|
| 用户处境 | 领域/资源/入场状态 |
| 选定方向 | 主推+Backup, 含 claim + H1 + 评级 |
| 完整 10 候选清单 | 表格, 含贡献类型+评级 |
| 检索元信息 | query/时间窗/检索数 |

## 校验流程

实验阶段开始时, 读所有 `idea-spec-I*.md` (可能多份) + `references.md`, 逐字段校验:

1. 必须字段全部非空 → 进 Phase 1
2. 有必须字段缺失 → 退回, 列出缺失清单, 要求补全后重新进入
3. 字段内容明显不完整 (e.g. H1 无量化判据，或"设计思路/核心创新点"两个灵魂节空泛) → 警告但放行, 提示"建议补全后再实验"

## 和 ideation skill 的关联

ideation skill 的 Step 6 落盘时, 必须严格按 ideation 的 `templates/idea-spec.md` (9 节, 含"设计思路/核心创新点"两个灵魂节, 不含实验设计) 输出, 本契约与该模板保持同步。实验阶段不做"从对话历史推断 idea", 只读磁盘文件。
