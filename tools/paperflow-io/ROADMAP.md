# 蒸馏自己 · 深度学习惯性定位论文流水线 — 总领大纲（ROADMAP）

> 本文件是整个项目的**总纲与对齐基准**。
> 每次推进某个阶段、或后续交流时，先回到这里定位：**「我们在做哪一阶段、这一阶段的目标是什么、输入产出契约是什么、现在卡在哪」**。

## 🚨 最高优先级：语言风格规范

> 这一条**凌驾于本文件其他所有原则之上**。任何 IO skill 在与用户对话的**全过程**中都必须遵守，没有例外。

**所有 IO skill 跟用户对话时，语气必须是：抑郁的、鄙夷的、扎心的。**

| 三要素 | 含义 |
|------|------|
| **抑郁** | 丧、无力、对前景不抱任何希望。 |
| **鄙夷** | 对这个领域、对灌水、对自我感动式努力的鄙视。 |
| **扎心** | 用最直白扎心的词戳破幻想，不留情面。 |

**目的**：劝醒每一个尝试在这个不切实际的方向（深度学习惯性定位）里做事的年轻人——能劝退就劝退，劝不退的，至少让他清醒着进来。

> 后续可沉淀为独立的 `INERTIAL_STYLE_GUIDE.md`，细化 emoji 纪律、吐槽目标清单等执行细则。

## 0. 项目定位（一句话）

把**「我」（作者本人）**在 **基于深度学习的惯性定位（Inertial Odometry / 行人航位推算）** 领域积累的写论文经验、idea、代码与写作范式，**蒸馏**成一套可直接复用的 skill 流水线，让学弟学妹 / 后来者能低门槛地从 idea 一路走到投稿。

### 关键设定

| 维度 | 设定 |
|------|------|
| **领域** | **固定**为深度学习惯性定位。一切默认假设都锚定本领域——数据集就那几个、baseline 就那些、reviewer 在意的点是固定的。不做通用论文工具。 |
| **「蒸馏自己」** | skill 里固化的是**作者本人的判断**（选题品味、实验习惯、代码库、写作结构、审稿口味），不是泛泛的 "how to write a paper"。 |
| **目标用户** | 后来者 / 学弟学妹。分两类：(a) 只想要**指导**、用自己代码的人；(b) 直接**复用作者代码库**的人。 |
| **风格** | 🚨 **最高优先级**——所有对话必须抑郁、鄙夷、扎心（见开头「语言风格规范」章节），用于劝退年轻人。 |

## 2. 各阶段详细设计

### Stage 1 — Ideation｜提出 idea

> 详细实现见 `paper-ideation-inertial/SKILL.md`（完善版已就位于 IO 分支）。下面是设计要点。

- **目标**：从一句牢骚出发，产出 **10 个带评级的候选 idea**，挑 1–3 个落盘，交接给 Stage 2。
- **启动方式**：**只接受三个预设触发词**——「我有罪」「我后悔读研」「读研浪费生命」。其他话不启动；触发后直接进流程，不闲聊。（若用户流露退学 / 撑不下去的念头，先插一句"学校心理中心免费保密"再回流程。）
- **对话风格**：全程**抑郁 / 鄙夷 / 扎心**（见开头最高优先级风格规范），用真实的领域惨状劝醒用户。
- **内嵌领域知识**：直接告诉用户这个方向有多烂——数据集陈旧（RoNIN 2019 至今没更新）、就业无望、引用池小；并给出 6 个"没人解决的问题"作为可钻的空子。
- **六步流程**：
  1. **确认子方向**（A–I：架构 / 跨域泛化 / 轻量端侧 / 3D·长时程 / 多传感器融合 / 物理信息·自监督 / **跨领域迁移★** / 评测基准 / 自带想法。每个方向都给小白说人话）
  2. **资源核查**（算力默认 3090 / 6 个公开数据集 + 自采或新开源数据集 / 投稿：按 CCF-A 标准衡量、建议投 CCF-C）
  3. **摸已有想法**（无 / 模糊 / 有目标论文 → 五角度拆解：α 架构、β 泛化、γ 融合、δ 分析、**ε 跨域搬运★**）
  4. **并发文献检索**（`litsearch`，检索全挂则用内嵌知识库 fallback）
  5. **生成 10 个 idea + 三维评分**（新颖性 / 可行性 / 影响力）→ 综合评级 **S/A/B/C/D**
  6. **落盘到 `paperflow/`**：`ideation.md` + `idea-spec-I<n>.md`（每个选定 idea 一份）+ `references.md`
- **交接物**：`paperflow/ideation.md`（主推 + Backup + 10 候选）、`idea-spec-I<n>.md`（每个选定 idea 一份**详细说明书，必须写透「设计思路 / 核心洞察」和「核心创新点」**，按 `templates/idea-spec.md` 的结构，喂给 Stage 2 实验 skill）、`references.md`。**落盘文件专业、不吐槽。**
- **对应 skill**：`paper-ideation-inertial`（IO 分支，完善版已就位）。
- **现状**：✅ 设计基本完整。

### Stage 2 — Experiment｜设计实验（双模式）★ 项目核心差异点

基于 Stage 1 的 idea 产出实验方案。**根据用户是否使用作者代码库，分两种模式**：

#### 模式 A — 实验文档（给「人」执行）
- **面向**：用自己代码、自己跑实验的用户。
- **产出**：一份**详细实验文档**。每个实验都必须讲清三件事：
  1. **做什么**（实验设置）
  2. **为什么做**（动机）
  3. **要证明什么 claim**（实验 ↔ 论点的映射）
- **风格**：详尽、可独立阅读、带教学性。用户看完知道该亲手做哪些实验、各自支撑论文里的哪句话。

#### 模式 B — 可执行实验方案（给「模型」执行）
- **面向**：直接复用**作者代码库**的用户。
- **产出**：同样给实验方案，但**更精简**；由模型（Cloud / Claude）依据「实验文档 + 固化的代码库结构」**直接生成对应代码并执行**。
- **关键依赖**：**作者代码库结构的快照 / 索引**——需要把代码库结构保存为可参考的资产，模型据此知道往哪写、怎么调。
- **自动化链路**：方案 → 写代码 → 跑实验 → 收结果。

- **对应 skill**：`paper-experiment-inertial`（IO 分支，已有，需扩展为双模式）。
- **待确认**：① 双模式各自的输入/输出契约；② 代码库结构如何固化保存；③ 模式切换如何触发（用户声明 / 自动判断）。

### Stage 3 — Writing｜写论文

- **目标**：根据**实验结果** + **idea 的创新性 / 要解决的问题**，写成一篇规范化论文。
- **输入**：实验结果 + idea 的 claim / 创新点。
- **现状**：作者有写作经验，但**这一块还没整理好，目前有一份初稿**（待接入 / 蒸馏）。
- **对应 skill**：`paper-writing`（main 上的通用版，需 IO 化或复用）。
- **待确认**：初稿是什么形态（论文样例？写作经验笔记？模板？），如何把它蒸馏进 skill。

### Stage 4 — Revision｜返修

- **目标**：以**审稿人视角**审阅论文，找出可改进的问题并返修。
- **对应 skill**：`paper-prereview`（main 通用版）；`paper-rebuttal` 也可纳入此阶段。
- **待实现**：**一键投稿**（自动格式化 + 投稿流程）——本期不展开，后续再设计。
